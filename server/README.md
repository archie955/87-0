# server

FastAPI backend for 87-0. Async SQLAlchemy + Postgres, Redis for the active-game cache, JWT auth (email/password and Steam OpenID), managed with [uv](https://docs.astral.sh/uv/).

## Setup

```bash
uv python install 3.12   # if you don't already have it
uv sync --group dev
cp ../.env.example .env.dev   # fill in the blanks
```

You'll need Postgres and Redis reachable at whatever `.env.dev` points at - the easiest way is `docker compose -f docker-compose.dev.yml --env-file .env.dev up --build`.

Run migrations, then start the app:

```bash
uv run alembic upgrade head
uv run uvicorn main:app --reload
```

The app also self-seeds its `teams`/`players` tables from `database/*.csv` on first boot if they're empty (see `main.py`'s `lifespan`), so a fresh database doesn't need a separate seed step.

API docs are served at `/docs` once the app is running.

## Tests

```bash
uv run pytest
```

Needs its own Postgres/Redis, separate from your dev ones - see `docker-compose.test.yml` (`uv run pytest` against those is exactly what CI does). Coverage is on by default (configured in `pyproject.toml`); add `--cov-report=html` for a browsable report in `htmlcov/`.

## Linting & type checking

```bash
uv run ruff format .      # formats in place
uv run ruff format --check .   # CI's version - fails instead of fixing
uv run ruff check .
uv run pyrefly check
```

## Project layout

- `alembic/` - Alembic migrations and environment, mostly autogenerated
- `authentication/` - JWT creation/verification, auth dependencies
- `cache/` - Redis cache setup and seeding
- `database/` - Engine/session setup, plus the CSV-seeding scripts
- `exceptions/` - Custom exceptions classes
- `logger/` - Logging setup and custom logging middleware
- `ml/` - Machine learning model production, pickled model
- `models/` - SQLAlchemy ORM models
- `routers/` - FastAPI route definitions, one file per resource
- `schemas/` - Pydantic request/response models
- `services/` - Business logic, called from routers
- `tests/` - See `tests/conftest.py` for the fixture layout (`client`, `db`, `helpers`, `auth_client`)
- `utils/` - Settings configuration and password hashing

## Dependency groups

`pyproject.toml` splits dev-only tooling into groups (`lint`, `test`, `data`) rather than lumping everything under one `dev` extra, so CI can install only what a given step needs (`uv sync --no-default-groups --group test` for the test job, for instance) instead of always pulling in pandas/numpy/ruff/pyrefly regardless of what's actually being run.
